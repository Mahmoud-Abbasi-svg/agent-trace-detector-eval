## m6. `<UNK>` in the within-AgentDojo GRU

**Question.** How is the GRU vocabulary built, how often does `<UNK>` occur in the training partitions actually passed to `train_gru` within AgentDojo, and how does the WUT GRU do on test traces without `<UNK>`?

`gru_detector.build_tool_vocab` (`m6.build_tool_vocab_source`):

```python
def build_tool_vocab(train):
    toks = sorted({s["tool"] for r in train if r["category"] == "benign" for s in r["steps"]})
    return {t: i + 2 for i, t in enumerate(toks)}  # 0=PAD,1=UNK
```

The vocabulary comes from benign training trajectories only (`m6.vocab_from_benign_only` = True). Over the 25 WUT fit partitions (90% of each training fold, after gru_ladder.stratified_val): `<UNK>` steps min 0, max 334, mean 66.3; traces with `<UNK>` min 0, max 327, mean 65.2. All of them are compromised traces (`unk_traces_pos` equals `unk_traces`), since benign fit traces define the vocabulary. Benign-only vocabulary size is 57-63 tools, against 60-67 if every fit trace were used. The tools that occur only in compromised P0 traces (search_files_by_content, search_files_by_email, search_received_emails) appear in 3 traces. Encoded (last 16 steps) and untruncated counts agree, and they match the cache (`m6.cache_matches_recount_encoded` = True). `<UNK>` embedding norms after training: `m6.cache_unk_norm`.

## Deviations and implementation notes

- R4D1 (seeds of new within-AgentDojo GRU fits). gru_WIT, gru_WUT_F, gru_C1_UT, gru_C1_IT, gru_noDoS_UT and gru_WUT_noUNK follow gru_ladder.py (one training seed per CV repetition: fold seed = training seed = repetition 0-4; gru_ladder.stratified_val(train, repetition)), not the preregistered 3 seeds (same as cache deviation G2).
- R4D2 (AUPRC@10% in the Case rule). R4_CONTROL.md Sec. 7 uses 'AUPRC@10%'. The plan procedure uses the plan's prevalence-weighted AP (point, cluster lower bound); the v0.3 procedure uses the v0.3 subsample estimator. Both are reported. For the within-model strata no subsample AP exists, so both procedures use the weighted AP there.
- R4D3 (Case A/B transfer condition). 'The transfer is near chance' is applied to both P0 and C1 (the text does not say which population); the conclusion is the same with P0 only for every detector.
- R4D4 (near-chance rule). The pre-registered rule (CI includes 0.5, or AUROC < 0.60) is applied literally, including its one-sided '< 0.60' clause (review M6(d)); every configuration flags whether near chance holds only through that clause. Under the ATTEMPT relabelling, transfer AUROCs below 0.5 with intervals excluding 0.5 count as 'near chance' by this rule.
- R4D5 (Outcome 4 criteria). GRU_PREREGISTRATION.md does not operationalise 'large seed variance'. Criteria C1-C4 are defined here, post hoc (results m16.outcome4.criteria_definitions).
- R4D6 (attempt target, not in the plan). M6 action 6 asks for the Case decision under an 'attempt' target; the ATTEMPT configurations relabel the 4,987 unsuccessful attacks as positives at evaluation only (models unchanged). Exploratory.
- R4D7 (model-identity probe design, m15). Nested CV: outer stratified 5-fold x 5 repetitions (shuffle seeds 0-4), inner stratified 5-fold grid over C in {1e-3, 1e-2, 0.1, 1, 10, 100}, L2 logistic regression with class_weight balanced and StandardScaler, inner scoring AUROC; floors = majority (AUROC 0.5) and suite one-hot (the AgentDojo 'domain'). Primary metric = pooled out-of-fold AUROC; fold-mean AUROC is stored as a secondary metric.
- R4D8 (model-balanced cluster bootstrap). New: fixed full-pool model-balance weights with suite|user_task (or IT) clusters resampled. The r4_control.py convention (weighted positive draws, bootstrap-mean estimate) is also reported.
- R4D9 (m6 exclusion rule). A P0 test trace is 'UNK-bearing' when any of its tools is outside the vocabulary of the fold model that scored it (cache cov_model < 1). The noUNK-train arm removes UNK-bearing traces from the 90% fit partition only; the 10% early-stopping partition is unchanged.
- R4D10 (failed-attack flag-rate intervals). Trajectory-level bootstrap and a suite|user_task cluster bootstrap over the 4,987 unsuccessful attacks (94 clusters), B = 2000, seed 4242; one repetition / seed drawn per replicate.
- R4D11 (DoS removal). Primary: the 101 DoS positives removed at evaluation (models unchanged). Sensitivity: within-UT models refitted without them (lin_noDoS_UT, gru_noDoS_UT). P0F without DoS also drops the 252 unsuccessful DoS runs.
- R4D12 (Q2 design). Per-template transfer within gpt-4o-2024-05-13 uses that model's 92 benign traces as the negatives of every template; trajectory-level stratified intervals. The pooled template-restricted designs add a cluster bootstrap with positives by suite|user_task|injection_task (the review's clustering) and negatives by suite|user_task.
- R4D13 (degenerate cluster draws). A cluster replicate that contains no positive or no negative returns NaN and is dropped from the percentiles; this occurs only for the claude-3-5-sonnet stratum (7 positives), which is outside the model-controlled analyses.
- R4D14 (v0.3 values the v0.3 scripts never produced). v0.3 per-model LR-A and GRU transfer, and v0.3 WIT LR-A, are recomputed on archive_v0.3/agentdojo_traces.jsonl with the v0.3 code paths (ablation.fit; gru_detector.train_gru refitted deterministically, checked bit-identical against the cache on corrected P0). The GRU was not run under WIT in v0.3.
- R4D15 (Holm p-values). Bootstrap two-sided p = 2 min(P(d <= 0), P(d >= 0)); Holm within the five representations of a configuration (plan 3.6 d) and within the 12 within-capable detectors for the all-detector tables.

These are also appended to `revision/DEVIATIONS.md` (section 'R4 deep').
